# Web app

Scope: `apps/web` (`tag-app-web`), the React SPA that browses and edits the library: routes, state, the oRPC client and the extension handshake. Components and shadcn rules: [ui components](./ui-components.md). Dev-only fake-server pages: [mock pages](./mock-pages.md).

## Setup

- Vite + React, wouter with the hash router (`useHashLocation`), TanStack Query via `@orpc/tanstack-query`, Jotai, Constate. Alias `@/` is `apps/web/src`.
- Builds into `apps/server/dist/WebUI` ([deployment](./deployment.md)). The oRPC client posts to `${location.origin}/rpc` (`src/lib/orpc.ts`) and media URLs are same-origin `/media/...`, so `vite.config.ts` proxies `/rpc` to the server (`localhost:5001`, the default in `db/settings.ts`) and `/media` to Caddy (`localhost:5000`). `bun dev:web` therefore needs `bun dev:server` and Caddy running for real data (change the constants if `settings.json` uses another port); the [mock pages](./mock-pages.md) need neither.
- `src/App.tsx`: router, theme, toaster, confirm dialog, the extension message listener, and the dev-only `#/mock` route. `src/AppLayout.tsx`: nav bar and route table, shared with the mock pages. Query client defaults: no refetch on focus or mount, `retry: 1`.

## Routes (`src/routes`, lazy loaded in `AppLayout.tsx`)

| Hash route                                                     | Page                         | Notes                                                                                                                                                                                                           |
| -------------------------------------------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                                                            | `routes/index.tsx`           | Library: filters, results, selection, edit, bulk edit, "Sync library". Wrapped by `contexts/Server.Context.ts`                                                                                                  |
| `/sync`                                                        | `routes/sync/index.tsx`      | Sync preview (`main.getSyncData`): own filters, edit / remove pending items, Refresh (rescan only) and Sync                                                                                                     |
| `/downloads`                                                   | `routes/downloads/index.tsx` | Server download queue and history as cards with live progress (`downloads.watch` plus the library lookup for finished covers); "Start downloads", cancel, remove, clear, error log dialog                       |
| `/tags`                                                        | `routes/tags.tsx`            | Tag counts, `hardResetTagCount`, `softResetTagCount`                                                                                                                                                            |
| `/settings`                                                    | `routes/settings.tsx`        | Device-local gallery defaults (sort, layout, single-column width, autoplay) and group display (position in the library); nothing goes to the server                                                             |
| `/group`                                                       | `routes/group/index.tsx`     | Every group incl. empty ones: search, Fix Data, per card edit / fix / disband / delete, select then merge / disband / delete. Fetches `main.getAllContent` and `groups.list` itself (`useQuery`, fresh on open) |
| `/group/:id`                                                   | `routes/group/[id].tsx`      | A group: the library page scoped to its children, plus a header with cover, description, tags, Stats, Edit, Fix Data, Disband and Delete group. Unknown id: "Group not found"                                   |
| `/reference`                                                   | `routes/reference.tsx`       | Renders `Notes/TagApp Server Reference.md` (`?raw` import)                                                                                                                                                      |
| `/img/:id` `/video/:id` `/gallery/:id` `/txt/:id` `/audio/:id` | `routes/<type>/[id].tsx`     | Item pages inside `DocProvider` (`contexts/Doc.Context.tsx`); anything else gets `404.tsx`                                                                                                                      |

- Page code lives in `routes/<type>/`, shared pieces in `routes/components/`, generic pieces in `components/`.
- `DocProvider` sits inside a route matching `DOC_ROUTE`; without that wrapper `Switch` would match it for every URL and the 404 would never render.
- Media URLs are built from `encodeURIComponent("<title>.<id>")` against `/media/...` ([deployment](./deployment.md)).
- Item notes (`DocInfoSection`) and text chapters (`routes/txt/[id].tsx`) render markdown with `rehype-raw` then `rehype-sanitize` (default schema), so embedded HTML is allowed but scripts, event handlers and `<iframe>`/`<video>` are stripped. `/reference` renders a bundled file without sanitizing.

## State

- `src/atom.ts`: theme (`localStorage` key `vite-ui-theme`), filter atoms, `FilterQueryAtom`, `filterActiveAtom` (separates "empty library" from "no results") and `tagsAtom`. `realtimeFilterAtom` (`localStorage` key `realtime-filter`) is the "Realtime" switch in the filters panel. Filters are mirrored into the URL query (`any`, `all`, `none`, `types`, `search`, `orderByLatest`) by `injectFilterDataIntoURLAtom` and read back on load.
- Filtering is client-side: the library page loads everything once (`main.getAllContent` and `groups.list` together, one mutation) into `allContentAtom` and `allGroupsAtom` and runs the shared `filterLibrary` into `filteredAtom`, a `LibraryEntry[]` of item rows and group cards (`Server.Context.ts`; rules: [domain model](./domain-model.md#library-filter-filterlibrary)). The Filter button applies the filters; with Realtime on, a debounced effect (200 ms) re-filters whenever `FilterQueryAtom` changes and updates the URL with `replaceState`. Sync and every group change refetch everything; edit, bulk update and delete patch both lists in place (`patchContent` maps the result by id into the shown rows and card children, and a card left without children drops out).
- Groups in the library: `FilterQueryAtom` also carries `showGrouped`, `itemsOnly` (advanced search mode 2; mode 1 is the default, the two are exclusive buttons), `searchDescription` (independent), `groupSort` and `groupedInLibrary`. The three flags are URL params (`showGrouped`, `itemsOnly`, `searchDescription`, absent = off) set by `injectFilterDataIntoURLAtom` and read back on load; "Show grouped items" is disabled in mode 2 (which lists every item). `AdvancedSearch` sits in the `FilterPanel` `extra` slot. `groupSortAtom` (`group_sort`) and `groupedInLibraryAtom` (`grouped_in_library`, `"hide"` default or `"show"`) are device-local `atomWithStorage` atoms set on the Settings page (Groups section: selects "Group position in the library" and "Grouped items in the library" with the options "Hidden unless tagged view:in-library" / "Shown unless tagged view:hide-in-library"); they apply the next time the list is filtered. In `show` mode `AdvancedSearch` does not render "Show grouped items", the item edit modal's "Also show in the main library" switch is not offered, the filter count ignores `showGrouped`, and on `/group/:id` the selection actions "Show in library" / "Hide from library" remove / add `view:hide-in-library` (`Filters`) instead of adding / removing `view:in-library`. Group cards (`ExtendedGroupCard` over the shared `components/craft/library/GroupCard`: cover, title, id, tags, "Group · N items") link to `/group/:id` through wouter; their actions are icon buttons **Edit** (opens one `GroupEditModal` mounted by the library page) and **Disband** (`confirm.destructive`, then `groups.disband`), hidden without `tagsAtom` like the other changing controls. The card shows the group's own tags, then the union of its children's (`GroupCard` `childTags` → `TagChips` `extra`: a second section under a border, only the rows the collapsed limit leaves, tags already own not repeated, one "Show N more"); `/group` cards pass `childTags` too. Cards are not selectable: selection, Select all and the item count work on the item rows (`entryItems`), and the results bar adds ", M groups". Clicking a card runs `clearFilterForNavigationAtom` first, because the filters live in `location.search`, before the `#`, and would follow the user to the next route. A card's cover is the group's own `cover` URL as stored (set once by the server, [groups](./groups.md#cover)); an empty one, or an image that fails to load, shows the no-cover icon (`ImageOff`).
- Add to group: `AddToGroupModal` (open it by setting `addToGroupAtom` to the item ids; mounted once on the library) holds a `GroupPicker` (existing groups only; creating a group is `/group`'s "New group") and calls `useGroupActions(...).addToGroups(itemIds, groupIds)`, which runs `groups.addItems` for every target. The entry point, hidden without `tagsAtom`, is "Add to group…" in the selection bar (the library has no floating toolbar; that one is the gallery's); there is no per-card button, a single item joins a group in its edit modal. `useGroupActions(onChanged)` invalidates `groups.*` queries and calls `onChanged` (the library passes `loadAllContent`, which reloads items, groups and tag counts) after each successful call, and toasts errors. The item edit modal takes an `extra` slot: the library and `/group/:id` fill it with `ItemGroupsField`: one `MultiSelect` bound to `updateGroupsAtom` (existing groups only, like the extension's `GroupsField`) and the switches "Also show in the main library" (`view:in-library`, shown once the pending groups are non-empty and Settings hides grouped items) and "Hide from the main library" (`view:hide-in-library`, always), which only edit the tags box. Group edits touch only `updateGroupsAtom` (group ids, in `UpdateModal/atom`, part of `updateDataAtom`); whoever opens the modal sets it from the item (`ExtendedCard`, `DocInfoSection`, `Doc.Context` after load and save), so Cancel discards them. Save sends `groups` with title and tags in one `main.setContent` call (`[]` clears them). After a save whose groups changed, the library page reloads items and groups (`loadAllContent`; rows and cards move, a group may get its cover) and the item page refetches `groups.list`. Item pages (`/img/:id`…) fill the slot too: `Doc.Context` loads `groups.list` and passes `ItemGroupsFieldView` (the prop-driven part, `groups` only; the default export reads the library atoms). The read-only "Groups" row of `DocInfoSection` (saved `doc.groups`, shown once `groups.list` has loaded, hidden when empty) uses `routes/components/ItemGroupLinks.tsx` (`GroupLink`: link to `/group/:id` with `clearFilterForNavigationAtom`, plain text for an id without a record; `ItemGroupLinks`: the chip row). The full feature: [groups](./groups.md).
- Group pages: `/group` (`routes/group/index.tsx`) keeps its own data in two `useQuery` calls (`main.getAllContent`, `groups.list`; `gcTime: 0`, `refetchOnMount: "always"`) and derives children with `childrenByGroup`; after each action `useGroupActions(reload)` invalidates `groups.*` and refetches the content. "New group" opens `NewGroupModal` (title; `groups.create` with the default id). Cards are the shared `GroupCard` with `selection` and icon `actions`; Merge is `MergeGroupsModal` (radio list of the selected groups, `groups.merge`), bulk Disband loops `groups.disband`, Delete queues the selected groups through `DeleteGroupModal` one after another, and Edit opens `GroupEditModal` (also the way to change the id: `groups.changeId`). The modal reuses `UpdateModal`'s `Field` and `SeeMore`: Title and Tags (the group's own) on top, Cover URL, Description and Id under "More fields".
- `/group/:id` (`routes/group/[id].tsx`) wraps the library's `ServerProvider` with `groupId` (keyed by id): `runFilter` then keeps only the items whose `groups` contain the id and calls `filterLibrary` with `itemsOnly` and no groups, so the page has the library's filters, selection, `UpdateModal`, `BulkUpdateModal`, edit and delete unchanged and no cards. `Filters` takes `onRemoveFromGroup` there: the advanced search shows only "Search descriptions too", the selection bar gets "Remove from group" (`groups.removeItems`) and the delete button says "Delete" (`main.removeContents`). `GroupHeader` shows the cover (the group's `cover`, the no-cover icon when empty), the markdown description (`rehype-raw` + `rehype-sanitize`, like item notes), tags and the actions; `GroupStatsModal` is `groupTagStats` in a `ModalShell`; `GroupEditModal` saves title, description, tags and cover through `groups.update` (`cover: ""` clears) and a changed id through `groups.changeId` (then the page navigates to the new id). "Choose cover" (`Filters` with `onRemoveFromGroup`, `coverModeAtom` / `toggleCoverModeAtom` in `atom.selection.ts`, exclusive with selection) sits beside "Select items"; while on, the page passes `onPickCover` to `ExtendedCard` → `ContentCard`, whose click picks instead of selecting and whose link and buttons are inert; the pick opens `CoverConfirmModal` (`components/craft`: preview, editable URL, "Set cover"), which calls `groups.update` with `/${getCoverUrl(item)}` (or the edited URL) and leaves the mode; `/gallery/:id` cover mode opens the same modal (gallery-relative path editable, `setCoverMutation`). `confirmCover` stays for removing a cover and the txt/audio pages (an item without a cover only toasts; the mode is also reset on unmount). Disband goes to `/`, Delete group (`DeleteGroupModal`, [groups](./groups.md)) to `/group`. The page clears the filters on unmount (atoms and URL) so they do not leak into the library, and resets `filteredAtom` on mount so the library's rows never flash. A back/forward move therefore comes back unfiltered.
- `/sync` keeps its own filter state in component state (`useState`, not the library's atoms or URL query) and filters `getSyncData().contents` with the same `filterData`; it shares only `realtimeFilterAtom`. The scan is a `useQuery` refetched on open and after edit, remove and sync. It reuses `FilterPanel`, `ContentCard` with covers, raw-file links and an inline video player (with caption) from `/media/.sync/...` ([deployment](./deployment.md#caddy-appscaddyfile)), and `UpdateModal` (edit stays in the global update atoms, so only one page uses it at a time). An image with no cover yet shows the image itself, since its cover is generated at sync. Each pending item with `groups` shows the shared read-only Groups row (`ItemGroupLinks`; titles from `groups.list`, fetched beside the scan; unknown ids are plain text). Controls need `tagsAtom` like the library.
- `/downloads` shows the server's merged list as it is (`DownloadsSnapshot.tasks`: queue in order, then completed history newest first, each with `queuedAt`/`startedAt`/`finishedAt`, scraper, remote `cover` URL, and for completed ones `type` and `added`: [server downloads](./server-downloads.md#history-and-the-snapshot)); no queue query and no client-side merge. The page is a card grid in three sections with counts, in this order (empty ones are not rendered): "Active and queued", "Failed and cancelled", "Finished" (newest first, as the server sends it). A card (`routes/downloads/components/DownloadCard.tsx`) has a 16:9 cover with the status chip on top and a `role="progressbar"` fused to its bottom edge (full for completed, pulsing while importing, none while queued), the title, id, a status line (percent, speed and ETA while downloading; "Importing into the library…"; "Stopped at N%"), the error when failed (clamped to 3 lines, click to expand), the dates it has (Added to downloads, Started, Downloaded/Failed/Cancelled, Added to library; `lib/formatDate.ts`, the format of the library cards), and a footer with the scraper and the action. The cover of a completed item still in the library is its local cover (`getCoverUrl` from `@tagapp/utils`, the library card's builder) looked up by id in `main.getAllContent` (`useDownloads` fetches it, refetched when the completed count changes) and the title/cover link to `/#/<type>/<id>`; otherwise the remote `cover` URL (`referrerPolicy="no-referrer"`, lazy) and, when it is missing or fails to load, a placeholder with the type icon and the scraper. A `queued` card says "Waiting in the queue" until a run picks it up (it has Cancel while a run is going, Remove otherwise). The stream is `orpc.downloads.watch.experimental_liveOptions` (keeps only the latest snapshot); `gcTime: 0` + `refetchOnMount: "always"` mean leaving the page aborts the request and coming back reconnects, and a stream error is retried 4 times with React Query's backoff before a "Reconnect" line shows. The library needs no invalidation: it reloads `main.getAllContent` (a mutation) every time it mounts. Controls (all hidden without `tagsAtom`, like the other changing controls; viewing progress is always allowed): Start; "Cancel all" while a run is going and a per-card Cancel on `queued`/`downloading` cards (`downloads.cancel`; `importing` rows have none); a per-card Remove on not-started, failed and cancelled cards and "Clear failed" (every failed and cancelled row, behind `confirm.destructive`) (`downloads.remove`: they leave the queue and the history), a per-card Clear on completed cards (`clearFinished({ ids: [id] })`, no confirmation) and "Clear finished" (all completed rows, behind `confirm.destructive`, `downloads.clearFinished`: history only, the library is untouched); the stream delivers the result. "Error log" (always shown) opens `routes/downloads/components/ErrorLogDialog.tsx` on the stock `ModalShell`: `downloads.getErrorLog` in a scrollable monospace `<pre>` scrolled to the end (newest last), a note when the server cut it to the last 1 MB, Refresh, and "Clear log" (behind `confirm.destructive`, hidden without `tagsAtom`, `downloads.clearErrorLog` then a refetch). The page invalidates the query whenever the failed-task count changes, so an open dialog refetches and a closed one is stale (it also refetches on every open). Errors, e.g. a CONFLICT from a name clash in `Sync/`, show as toasts.
- Gallery media sizing: `Gallery.tsx` `layoutClasses` sets `--media-min`/`--media-max` per layout and `GalleryContentCard` applies them as min/max height on a full-width, `object-contain` image or video. Grids cap the height; the single-column list sets `--media-max:none`, so media has no height limit and fills the column (the width slider sets the column width).
- Gallery filtering: the gallery page has a "Filter" funnel button in the sticky `GalleryOptions` bar (hidden panel by default; a count badge shows the active filters while closed). The open `GalleryFilters` panel sits inside the same sticky container (capped at 60vh, scrolls inside), so it stays visible with the options bar; the list-layout "Column width" slider moved into that container too. State is local to the page (`useGalleryFilter`, like `/sync`; only `realtimeFilterAtom` is shared). It filters `galleryDataAtom` with `filterEntries` (`packages/utils`: the tag/type rules of `filterData`, fuzzy search on the file `name`, input order kept; [domain model](./domain-model.md#filtering)); tag options are the tags present in the gallery's files. Sorting, the cards, the floating toolbar (select all, count) and delete work on the filtered list; the page drops selected files that the filter hides. "N of M files" shows in the bar, and no matches shows an `EmptyState` with a clear-filters button. The state logic is `hooks/useFilterState.ts` (shared with `useSyncFilter`) and the fields are `components/craft/library/TagFilterFields.tsx` (shared by `SyncFilters` and `GalleryFilters`).
- Gallery selection: "Select files" in the floating toolbar (`FloatingButton.tsx`, only with `tagsAtom`) shows the count, Select all / none (filtered list, behind a confirm), "Edit tags" and "Delete selected". "Edit tags" (disabled with nothing selected) opens the library's `BulkUpdateModal` (`noun="files"`, `pending` disables Save), reusing `bulkUpdateModalOpenAtom`, `selectionTagsAtom` and `selectionTagsInitialAtom`; it is pre-filled with the tags every selected file has, Save sends the difference to `gallery.bulkUpdateContentTags` (no call when nothing changed), patches `galleryDataAtom` with the result, closes the modal and keeps the selection, like the library. Errors toast. The toolbar unmount closes the shared modal atom. Tag options are `tagsAtom` (reserved tags included).
- `FilterPanel` layout: on small screens the order is search (full width), the fields, Realtime + Filter, then the clear-filters row; from `sm` the Realtime switch and Filter button sit right of the search (CSS `order` and grid placement, one markup).
- Gallery options (`routes/gallery/components/atom.ts`): the Settings page writes global defaults (`default*Atom`, `localStorage` keys `gallery_default_*`). The per-gallery families (`autoPlayFamily`, `sortModeFamily`, `galleryViewModeFamily`, `galleryListWidthFamily`, keys `gallery_<option>_<id>`) store `null` until the user changes that option on that gallery; reads return the gallery's own value or else the current default, so changing a default affects every gallery without its own choice. Precedence per option is own choice > `view:` tag > default: the gallery page parses the item's tags with `parseViewTags` (`packages/utils`) into `viewTagsFamily(id)` (a layout effect, so no flash), and the families read `own ?? tag ?? default`. Tags never write an override. "Reset" in the gallery options writes `RESET`, removing the own choices (back to tag, else default). Tag list: [domain model](./domain-model.md#view-tags). Labels for the select options live in `gallery/components/labels.ts`.
- `routes/atom.ts` (all items, result list, server tags), `routes/atom.selection.ts` (selection mode), per-type `atom.ts` files, `components/craft/UpdateModal/atom.ts`.
- Mutations replace objects instead of editing in place: memoised cards skip re-render on an identical reference.

## Extension handshake and read-only mode

- The TagApp browser extension (a separate project) posts `TAG_APP_INJECT_TAGS` with a string array via `window.postMessage`. `App.tsx` accepts it only when `event.source === window`, stores it in `tagsAtom` after appending the reserved tags (`withReservedTags`, [domain model](./domain-model.md#reserved-tags); extension order first, no duplicates, so the tag pickers always offer `meta:`/`view:` tags) and replies `TAG_APP_TAGS_RECEIVED`. The message may also carry `covers`, a tag -> cover URL record (older extensions omit it): `parseTagCovers` (`packages/utils/src/tagCovers.ts`) keeps only string entries whose value is an absolute `http(s)` URL (the page is a trust boundary: no `javascript:`, `data:` or relative paths) and the result replaces `tagCoversAtom` (`{}` when absent or invalid). The extension expands its `$Key` constants before sending; the Vault never expands anything. `/tags` passes `tagCoversAtom` to `TagGroups`, which shows the cover (lazy, `max-h-32`, `object-contain`, `referrerPolicy="no-referrer"`) above the row of each server tag that has one, like the extension's tags page. Tags that are not on the server show nothing; there is no cover without the extension.
- `tagsAtom` is `null` until then. While it is `null` the app is read-only: the library hides edit, remove and sync controls, item pages hide edit, remove and cover controls.

## Rules

- Titles are sanitized with `sanitizeStringForFileName` before `setContent`: [domain model](./domain-model.md#identity).
- The web app imports server types only (`import type { router } from "@tagapp/api"`); never server runtime code ([development](./development.md)).
- `src/lib/TIMEOUTS.ts` is a small timeout registry used by the library page.
