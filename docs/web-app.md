# Web app

Scope: `apps/web` (`tag-app-web`), the React SPA that browses and edits the library: routes, state, the oRPC client and the extension handshake. Components and shadcn rules: [ui components](./ui-components.md). Dev-only fake-server pages: [mock pages](./mock-pages.md).

## Setup

- Vite + React, wouter with the hash router (`useHashLocation`), TanStack Query via `@orpc/tanstack-query`, Jotai, Constate. Alias `@/` is `apps/web/src`.
- Builds into `apps/server/dist/WebUI` ([deployment](./deployment.md)). The oRPC client posts to `${location.origin}/rpc` (`src/lib/orpc.ts`) and media URLs are same-origin `/media/...`, so `vite.config.ts` proxies `/rpc` to the server (`localhost:5001`, the default in `db/settings.ts`) and `/media` to Caddy (`localhost:5000`). `bun dev:web` therefore needs `bun dev:server` and Caddy running for real data (change the constants if `settings.json` uses another port); the [mock pages](./mock-pages.md) need neither.
- `src/App.tsx`: router, theme, toaster, confirm dialog, the extension message listener, and the dev-only `#/mock` route. `src/AppLayout.tsx`: nav bar and route table, shared with the mock pages. Query client defaults: no refetch on focus or mount, `retry: 1`.

## Routes (`src/routes`, lazy loaded in `AppLayout.tsx`)

| Hash route                                                     | Page                         | Notes                                                                                                                                                                                                           |
| -------------------------------------------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                                                            | `routes/index.tsx`           | Library: filters, results, selection, edit, bulk edit, "Sync library". Wrapped by `contexts/Server.Context.ts`                                                                                                  |
| `/sync`                                                        | `routes/sync/index.tsx`      | Sync preview (`main.getSyncData`): own filters, edit / remove pending items, Refresh (rescan only) and Sync                                                                                                     |
| `/downloads`                                                   | `routes/downloads/index.tsx` | Server download queue and history as cards with live progress (`downloads.watch` plus the library lookup for finished covers); "Start downloads", cancel, remove, clear, error log dialog                       |
| `/tags`                                                        | `routes/tags.tsx`            | Tag counts, `hardResetTagCount`, `softResetTagCount`                                                                                                                                                            |
| `/generateContentJson`                                         | `routes/generateJSON.tsx`    | Builds a metadata JSON file to put in `Sync/` by hand; needs tags from the extension                                                                                                                            |
| `/settings`                                                    | `routes/settings.tsx`        | Device-local gallery defaults (sort, layout, single-column width, autoplay) and group display (position in the library, cover pick); nothing goes to the server                                                 |
| `/group`                                                       | `routes/group/index.tsx`     | Every group incl. empty ones: search, Fix Data, per card edit / fix / disband / delete, select then merge / disband / delete. Fetches `main.getAllContent` and `groups.list` itself (`useQuery`, fresh on open) |
| `/group/:id`                                                   | `routes/group/[id].tsx`      | A group: the library page scoped to its children, plus a header with cover, description, tags, Stats, Edit, Fix Data, Disband and Delete group. Unknown id: "Group not found"                                   |
| `/reference`                                                   | `routes/reference.tsx`       | Renders `Notes/TagApp Server Reference.md` (`?raw` import)                                                                                                                                                      |
| `/img/:id` `/video/:id` `/gallery/:id` `/txt/:id` `/audio/:id` | `routes/<type>/[id].tsx`     | Item pages inside `DocProvider` (`contexts/Doc.Context.tsx`); anything else gets `404.tsx`                                                                                                                      |

- Page code lives in `routes/<type>/`, shared pieces in `routes/components/`, generic pieces in `components/`.
- `DocProvider` sits inside a route matching `DOC_ROUTE`; without that wrapper `Switch` would match it for every URL and the 404 would never render.
- Media URLs are built from `encodeURIComponent("<title>.<id>")` against `/media/...` ([deployment](./deployment.md)).
- Item notes (`DocInfoSection`) and text chapters (`routes/txt/[id].tsx`) render markdown with `rehype-raw` then `rehype-sanitize` (default schema), so embedded HTML is allowed but scripts, event handlers and `<iframe>`/`<video>` are stripped. `/reference` renders a bundled file without sanitizing.

## State

- `src/atom.ts`: theme (`localStorage` key `vite-ui-theme`), filter atoms, `FilterQueryAtom`, `filterActiveAtom` (separates "empty library" from "no results") and `tagsAtom`. `realtimeFilterAtom` (`localStorage` key `realtime-filter`) is the "Realtime" switch in the filters panel. Filters are mirrored into the URL query (`any`, `all`, `none`, `types`, `search`, `orderByLatest`) by `injectFilterDataIntoURLAtom` and read back on load.
- Filtering is client-side: the library page loads everything once (`main.getAllContent` and `groups.list` together, one mutation) into `allContentAtom` and `allGroupsAtom` and runs the shared `filterLibrary` into `filteredAtom`, a `LibraryEntry[]` of item rows and group cards (`Server.Context.ts`; rules: [domain model](./domain-model.md#library-filter-filterlibrary)). The Filter button applies the filters; with Realtime on, a debounced effect (200 ms) re-filters whenever `FilterQueryAtom` changes and updates the URL with `replaceState`. Sync and every group change refetch everything; edit, bulk update and delete patch both lists in place (`patchContent` maps the result by id into the shown rows and card children, and a card left without children drops out).
- Groups in the library: `FilterQueryAtom` also carries `showGrouped`, `itemsOnly` (advanced search mode 2; mode 1 is the default, the two are exclusive buttons), `searchDescription` (independent) and `groupSort`. The three flags are URL params (`showGrouped`, `itemsOnly`, `searchDescription`, absent = off) set by `injectFilterDataIntoURLAtom` and read back on load; "Show grouped items" is disabled in mode 2 (which lists every item). `AdvancedSearch` sits in the `FilterPanel` `extra` slot. `groupSortAtom` (`group_sort`) and `groupCoverPickAtom` (`group_cover_pick`) are device-local `atomWithStorage` atoms set on the Settings page; the sort applies the next time the list is filtered. Group cards (`ExtendedGroupCard` over the shared `components/craft/library/GroupCard`: cover, title, id, tags, "Group · N items") link to `/group/:id` through wouter; their only action is **Disband** (`confirm.destructive`, then `groups.disband`), hidden without `tagsAtom` like the other changing controls. Cards are not selectable: selection, Select all and the item count work on the item rows (`entryItems`), and the results bar adds ", M groups". Clicking a card runs `clearFilterForNavigationAtom` first, because the filters live in `location.search`, before the `#`, and would follow the user to the next route. A card's cover is its own `cover` URL, else `groupCoverUrl`: the children's library cover URLs (`getCoverUrl`) through `pickGroupCover` with the cover-pick setting (a `media/…` result gets a leading slash); a failing image falls back to the placeholder.
- Add to group: `AddToGroupModal` (open it by setting `addToGroupAtom` to the item ids; mounted once on the library) holds a `GroupPicker` (pick existing groups and/or name a new one) and calls `useGroupActions(...).addToGroups`, which creates the new group (`groups.create`, id from `newGroupId`) and runs `groups.addItems` for every target. Entry points, all hidden without `tagsAtom`: a button on each item card and "Add to group…" in the selection bar (the library has no floating toolbar; that one is the gallery's). `useGroupActions(onChanged)` invalidates `groups.*` queries and calls `onChanged` (the library passes `loadAllContent`, which reloads items, groups and tag counts) after each successful call, and toasts errors. The item edit modal takes an `extra` slot: the library and `/group/:id` fill it with `ItemGroupsField` (the item's groups as links to `/group/:id` with a remove button each that applies at once, a `GroupPicker` for more, and the `view:in-library` switch, shown once the item has a group, which only edits the tags box and is saved with the item through `main.setContent`). Item pages (`/img/:id`…) fill it too: `Doc.Context` loads `groups.list` and passes `ItemGroupsFieldView` (the prop-driven part; the default export reads the library atoms) with `refreshGroups`, which refetches the groups and re-reads the doc with `main.getContent` into `doc` only, so what is typed in the modal is kept. The full feature: [groups](./groups.md).
- Group pages: `/group` (`routes/group/index.tsx`) keeps its own data in two `useQuery` calls (`main.getAllContent`, `groups.list`; `gcTime: 0`, `refetchOnMount: "always"`) and derives children with `childrenByGroup`; after each action `useGroupActions(reload)` invalidates `groups.*` and refetches the content. Cards are the shared `GroupCard` with `selection` and icon `actions`; Merge is `MergeGroupsModal` (radio list of the selected groups, `groups.merge`), bulk Disband loops `groups.disband`, Delete queues the selected groups through `DeleteGroupModal` one after another, and Edit opens `GroupEditModal` (also the way to change the id: `groups.changeId`).
- `/group/:id` (`routes/group/[id].tsx`) wraps the library's `ServerProvider` with `groupId` (keyed by id): `runFilter` then keeps only the items whose `groups` contain the id and calls `filterLibrary` with `itemsOnly` and no groups, so the page has the library's filters, selection, `UpdateModal`, `BulkUpdateModal`, edit and delete unchanged and no cards. `Filters` takes `onRemoveFromGroup` there: the advanced search shows only "Search descriptions too", the selection bar gets "Remove from group" (`groups.removeItems`) and the delete button says "Delete" (`main.removeContents`). `GroupHeader` shows the cover (own `cover` or `useGroupCover`), the markdown description (`rehype-raw` + `rehype-sanitize`, like item notes), tags and the actions; `GroupStatsModal` is `groupTagStats` in a `ModalShell`; `GroupEditModal` saves title, description, tags and cover through `groups.update` (`cover: ""` clears; quick picks are `/${getCoverUrl(child)}`) and a changed id through `groups.changeId` (then the page navigates to the new id). Disband goes to `/`, Delete group (`DeleteGroupModal`, [groups](./groups.md)) to `/group`. The page clears the filters on unmount (atoms and URL) so they do not leak into the library, and resets `filteredAtom` on mount so the library's rows never flash. A back/forward move therefore comes back unfiltered.
- `/sync` keeps its own filter state in component state (`useState`, not the library's atoms or URL query) and filters `getSyncData().contents` with the same `filterData`; it shares only `realtimeFilterAtom`. The scan is a `useQuery` refetched on open and after edit, remove and sync. It reuses `FilterPanel`, `ContentCard` with covers, raw-file links and an inline video player (with caption) from `/media/.sync/...` ([deployment](./deployment.md#caddy-appscaddyfile)), and `UpdateModal` (edit stays in the global update atoms, so only one page uses it at a time). An image with no cover yet shows the image itself, since its cover is generated at sync. Controls need `tagsAtom` like the library.
- `/downloads` shows the server's merged list as it is (`DownloadsSnapshot.tasks`: queue in order, then completed history newest first, each with `queuedAt`/`startedAt`/`finishedAt`, scraper, remote `cover` URL, and for completed ones `type` and `added`: [server downloads](./server-downloads.md#history-and-the-snapshot)); no queue query and no client-side merge. The page is a card grid in three sections with counts, in this order (empty ones are not rendered): "Active and queued", "Failed and cancelled", "Finished" (newest first, as the server sends it). A card (`routes/downloads/components/DownloadCard.tsx`) has a 16:9 cover with the status chip on top and a `role="progressbar"` fused to its bottom edge (full for completed, pulsing while importing, none while queued), the title, id, a status line (percent, speed and ETA while downloading; "Importing into the library…"; "Stopped at N%"), the error when failed (clamped to 3 lines, click to expand), the dates it has (Added to downloads, Started, Downloaded/Failed/Cancelled, Added to library; `lib/formatDate.ts`, the format of the library cards), and a footer with the scraper and the action. The cover of a completed item still in the library is its local cover (`lib/coverUrl.ts`, the library card's builder) looked up by id in `main.getAllContent` (`useDownloads` fetches it, refetched when the completed count changes) and the title/cover link to `/#/<type>/<id>`; otherwise the remote `cover` URL (`referrerPolicy="no-referrer"`, lazy) and, when it is missing or fails to load, a placeholder with the type icon and the scraper. A `queued` card says "Waiting in the queue" until a run picks it up (it has Cancel while a run is going, Remove otherwise). The stream is `orpc.downloads.watch.experimental_liveOptions` (keeps only the latest snapshot); `gcTime: 0` + `refetchOnMount: "always"` mean leaving the page aborts the request and coming back reconnects, and a stream error is retried 4 times with React Query's backoff before a "Reconnect" line shows. The library needs no invalidation: it reloads `main.getAllContent` (a mutation) every time it mounts. Controls (all hidden without `tagsAtom`, like the other changing controls; viewing progress is always allowed): Start; "Cancel all" while a run is going and a per-card Cancel on `queued`/`downloading` cards (`downloads.cancel`; `importing` rows have none); a per-card Remove on not-started, failed and cancelled cards and "Clear failed" (every failed and cancelled row, behind `confirm.destructive`) (`downloads.remove`: they leave the queue and the history), a per-card Clear on completed cards (`clearFinished({ ids: [id] })`, no confirmation) and "Clear finished" (all completed rows, behind `confirm.destructive`, `downloads.clearFinished`: history only, the library is untouched); the stream delivers the result. "Error log" (always shown) opens `routes/downloads/components/ErrorLogDialog.tsx` on the stock `ModalShell`: `downloads.getErrorLog` in a scrollable monospace `<pre>` scrolled to the end (newest last), a note when the server cut it to the last 1 MB, Refresh, and "Clear log" (behind `confirm.destructive`, hidden without `tagsAtom`, `downloads.clearErrorLog` then a refetch). The page invalidates the query whenever the failed-task count changes, so an open dialog refetches and a closed one is stale (it also refetches on every open). Errors, e.g. a CONFLICT from a name clash in `Sync/`, show as toasts.
- Gallery media sizing: `Gallery.tsx` `layoutClasses` sets `--media-min`/`--media-max` per layout and `GalleryContentCard` applies them as min/max height on a full-width, `object-contain` image or video. Grids cap the height; the single-column list sets `--media-max:none`, so media has no height limit and fills the column (the width slider sets the column width).
- Gallery filtering: the gallery page has a "Filter" funnel button in the sticky `GalleryOptions` bar (hidden panel by default; a count badge shows the active filters while closed). The open `GalleryFilters` panel sits inside the same sticky container (capped at 60vh, scrolls inside), so it stays visible with the options bar; the list-layout "Column width" slider moved into that container too. State is local to the page (`useGalleryFilter`, like `/sync`; only `realtimeFilterAtom` is shared). It filters `galleryDataAtom` with `filterEntries` (`packages/utils`: the tag/type rules of `filterData`, fuzzy search on the file `name`, input order kept; [domain model](./domain-model.md#filtering)); tag options are the tags present in the gallery's files. Sorting, the cards, the floating toolbar (select all, count) and delete work on the filtered list; the page drops selected files that the filter hides. "N of M files" shows in the bar, and no matches shows an `EmptyState` with a clear-filters button. The state logic is `hooks/useFilterState.ts` (shared with `useSyncFilter`) and the fields are `components/craft/library/TagFilterFields.tsx` (shared by `SyncFilters` and `GalleryFilters`).
- Gallery selection: "Select files" in the floating toolbar (`FloatingButton.tsx`, only with `tagsAtom`) shows the count, Select all / none (filtered list, behind a confirm), "Edit tags" and "Delete selected". "Edit tags" (disabled with nothing selected) opens the library's `BulkUpdateModal` (`noun="files"`, `pending` disables Save), reusing `bulkUpdateModalOpenAtom`, `selectionTagsAtom` and `selectionTagsInitialAtom`; it is pre-filled with the tags every selected file has, Save sends the difference to `gallery.bulkUpdateContentTags` (no call when nothing changed), patches `galleryDataAtom` with the result, closes the modal and keeps the selection, like the library. Errors toast. The toolbar unmount closes the shared modal atom. Tag options are `tagsAtom` (reserved tags included).
- `FilterPanel` layout: on small screens the order is search (full width), the fields, Realtime + Filter, then the clear-filters row; from `sm` the Realtime switch and Filter button sit right of the search (CSS `order` and grid placement, one markup).
- Gallery options (`routes/gallery/components/atom.ts`): the Settings page writes global defaults (`default*Atom`, `localStorage` keys `gallery_default_*`). The per-gallery families (`autoPlayFamily`, `sortModeFamily`, `galleryViewModeFamily`, `galleryListWidthFamily`, keys `gallery_<option>_<id>`) store `null` until the user changes that option on that gallery; reads return the gallery's own value or else the current default, so changing a default affects every gallery without its own choice. Precedence per option is own choice > `view:` tag > default: the gallery page parses the item's tags with `parseViewTags` (`packages/utils`) into `viewTagsFamily(id)` (a layout effect, so no flash), and the families read `own ?? tag ?? default`. Tags never write an override. "Reset" in the gallery options writes `RESET`, removing the own choices (back to tag, else default). Tag list: [domain model](./domain-model.md#view-tags). Labels for the select options live in `gallery/components/labels.ts`.
- `routes/atom.ts` (all items, result list, server tags), `routes/atom.selection.ts` (selection mode), per-type `atom.ts` files, `components/craft/UpdateModal/atom.ts`.
- Mutations replace objects instead of editing in place: memoised cards skip re-render on an identical reference.

## Extension handshake and read-only mode

- The TagApp browser extension (a separate project) posts `TAG_APP_INJECT_TAGS` with a string array via `window.postMessage`. `App.tsx` accepts it only when `event.source === window`, stores it in `tagsAtom` after appending the reserved tags (`withReservedTags`, [domain model](./domain-model.md#reserved-tags); extension order first, no duplicates, so the tag pickers always offer `meta:`/`view:` tags) and replies `TAG_APP_TAGS_RECEIVED`.
- `tagsAtom` is `null` until then. While it is `null` the app is read-only: the library hides edit, remove and sync controls, item pages hide edit, remove and cover controls, and Generate JSON shows a waiting state.

## Rules

- Titles are sanitized with `sanitizeStringForFileName` before `setContent`: [domain model](./domain-model.md#identity).
- The web app imports server types only (`import type { router } from "@tagapp/api"`); never server runtime code ([development](./development.md)).
- `src/lib/TIMEOUTS.ts` is a small timeout registry used by the library page.
